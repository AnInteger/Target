## Clarifications

### Session 2026-08-23

- Q: 全 App 页面内容左右边距统一到哪个值？ → A: **分层基准（Option D，用户裁定）**——hero 两屏（今日/回顾）维持 24 保大标题气势；次级四页（全部目标/我的/编辑器/详情）收敛 16 列表密度档（移动端行业默认基线，卡更宽、密度更优）；同层完全同线，跨层差异仅存在于 push 转场两侧（转场天然隔离层级读感）。全端单值 24 / 16 两案均弃。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 底部导航贴合屏幕底边（安全区适配）(Priority: P1)

我在全面屏手机上使用 App，无论有无 Home 指示条，底部导航的底幕都应一直延伸到屏幕物理底边——切换页面、滚动列表时下方不再出现露底断层；同时页签和＋按钮不会被 Home 指示条挡住。

**Why this priority**: 全面屏机型上 dock 下缘断层是当前最显眼的视觉缺陷，所有页面所有时刻可见；且属平台适配正确性问题而非风格偏好。

**Independent Test**: 在带底部安全区的机型（模拟器即可）上截屏：dock 底幕像素覆盖至屏幕底缘 y=0；页签文字与 Home 指示条不重叠。

**Acceptance Scenarios**:

1. **Given** 带底部安全区的设备，**When** 进入任意壳层页（今日/回顾/全部目标），**Then** dock 底幕紧贴屏幕物理底边，安全区内只有底幕背景延伸、无断层露底色。
2. **Given** 同设备，**When** 查看 dock 页签与中央＋位置，**Then** 所有互动元素完整避开 Home 指示区（不重叠、不遮挡），点击命中不变。
3. **Given** 无底部安全区的设备（旧机型/部分安卓），**When** 同上走查，**Then** 布局与现在一致，无多余空隙。

---

### User Story 2 - 全 App 页边距分层对齐（同层跨屏不跳动）(Priority: P1)

我在 dock 两页（今日/回顾）之间切换时，内容左右缘落在同一条线上；从今日进入全部目标、我的、编辑器、详情等次级页，这些页彼此也完全同线（更紧凑的列表档）——hero 屏透气、列表屏紧凑，各有恒定基准，整个 App 像一个产品而不是拼起来的四套页面。

**Why this priority**: 边距双标准是审查文档的根因项（「设计系统层」第一条），跨屏可见、逐屏修复其他项时都会撞到它；与 US1 同为 P1 因为它是「统一度量」的主干。

**Independent Test**: hero 两屏截屏叠加左右缘 x 坐标一致（24 气势档）；次级四页截屏叠加左右缘 x 坐标一致（16 列表档，全部目标/我的自 20 收敛）；两档差异仅出现在 push 转场两侧。

**Acceptance Scenarios**:

1. **Given** 今日页与回顾页，**When** dock 切换并截屏叠加，**Then** 两屏内容左右缘 x 坐标相同（hero 档基准）。
2. **Given** 全部目标/我的/编辑器/详情四个次级页，**When** 截屏叠加对比，**Then** 四屏内容左右缘 x 坐标相同（列表档基准）。
3. **Given** 全部目标页内的顶栏/筛选行/列表卡片，**When** 走查，**Then** 同屏内各元素左右缘一致，无页内二次缩进叠加。

---

### User Story 3 - 今日页关注轮播首卡对齐页边距（消叠加）(Priority: P2)

我在今日页左右滑动关注卡，第一张卡的左缘应与页面内容边距对齐；向右滑能看到邻卡露边（保留现有的「露边卡」peek 设计），但静止时首卡不再缩在离屏缘约 10% 的位置。

**Why this priority**: 叠加是今日页（首屏、使用率最高）最直观的布局缺陷，但只影响单组件，修法收敛，故 P2。

**Independent Test**: 今日页截屏量取：首卡左缘 = 页面内容左缘基准；滑到末张，末卡右缘 = 页面右缘基准；中间态邻卡可见露边。

**Acceptance Scenarios**:

1. **Given** 今日页有 ≥2 张关注卡，**When** 静止于第一张，**Then** 首卡左缘与页面内容左缘对齐（露边只出现在右侧邻卡）。
2. **Given** 同上，**When** 滑至最后一张，**Then** 末卡右缘与页面内容右缘对齐。
3. **Given** 单目标退化单卡，**When** 走查，**Then** 单卡左右缘均与页基准对齐，无滑动指示。

---

### User Story 4 - 导航切换有统一过渡、无残影（转场）(Priority: P2)

我在今日与回顾之间点 dock 切页，切换应有一个轻快统一的过渡（全局动效刻度单值），不再是 0ms 硬切；任何切换过程中看不到上一页残影或内容粘连。

**Why this priority**: 生硬是体感问题但无功能损失；残影项代码层未复现需真机复核——两者都收进转场统一这一条一起验收。

**Independent Test**: 手动连续快速切换 dock 两页 + push/pop 我的页/编辑器：有统一过渡、无残影、无双帧叠加；快速连点不卡死不错页。

**Acceptance Scenarios**:

1. **Given** 今日页，**When** 点 dock「回顾」，**Then** 切换有统一过渡动画（时长/曲线为全局动效刻度单值，非各页私设）。
2. **Given** 任意切换进行中，**When** 观察，**Then** 不出现上一页残影/半透明叠影/内容粘连（真机复核项并入本条验收）。
3. **Given** 快速连续切换多次，**When** 停止，**Then** 最终停在与所点页签一致的页面，状态不串（分支保留语义不变）。

---

### User Story 5 - 次级页顶栏同构与触达达标（细节一致性与可达性）(Priority: P3)

从今日页进入全部目标、我的、编辑器、详情等次级页，顶部返回栏应长一个样：同一返回键度量、同一标题字阶、同一高度与左右缘；所有小图标按钮（今日页铃铛、各页返回键等）的触达区域不小于 44pt，视觉尺寸可以更小。

**Why this priority**: 一致性收尾与可达性提升，都是低风险小改；放在最后避免与 US2 边距统一互相牵扯。

**Independent Test**: 次级页顶栏截屏叠加对比：返回键位置/尺寸一致、标题字阶一致、栏高一致；走查每个小图标按钮触达区 ≥44pt（视觉尺寸不变）。

**Acceptance Scenarios**:

1. **Given** 全部目标页与我的页，**When** 叠加对比顶栏，**Then** 返回键几何、标题字阶、栏内垂直对齐、左右缘完全同构。
2. **Given** 今日页头部，**When** 走查，**Then** 铃铛与头像的视觉中线与「今日」大标题的视觉中线对齐（不再与日期行+标题整块居中错位）。
3. **Given** 任一小图标按钮（铃铛/返回/日历等），**When** 量取触达区，**Then** 均 ≥44pt 且视觉尺寸与现冻结稿一致。

---

### Edge Cases

- 底部安全区为 0 的设备上，dock 不产生多余内边距（与现布局一致）。
- 横屏/大屏（iPad 分屏）下页边距分层基准仍成立（两档值不随屏宽漂移）。
- 轮播只剩一张卡时首末卡对齐同时成立（无 peek 冲突）。
- 转场动画进行中用户反向切换：过渡不撕裂、不错页、不停帧。
- 深浅两主题下以上全部走查各过一遍（断层/对齐/触达与主题无关，但阴影分层口径深色不同，不得引入重阴影）。
- 快速连点 dock 页签与＋：不重复入栈、不卡死（既有行为回归）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 使底部导航底幕延伸至屏幕物理底边：底部安全区内仅允许背景延伸，不得出现非底幕内容的断层露底。
- **FR-002**: 系统 MUST 保证 dock 内全部互动元素（页签/中央＋）完整避开底部安全区，且其可点命中区域不因适配而缩小。
- **FR-003**: 系统 MUST 使页面内容左右缘遵循受控分层基准——hero 两屏（今日/回顾）取气势档 24，次级 push 页（全部目标/我的/编辑器/详情）取列表档 16；同层各屏左右缘完全一致，同屏内不得出现页级与组件级边距叠加。
- **FR-004**: 今日页关注轮播 MUST 使首卡左缘、末卡右缘与页面内容基准对齐，同时保留邻卡露边（peek）形态与滑动行为。
- **FR-005**: 系统 MUST 为 dock 分支切换提供统一过渡动画：时长与曲线取全局动效刻度单值，全部路由共用，不得出现逐页私设参数或裸数值。
- **FR-006**: 任何页面切换过程 MUST NOT 出现上一页残影、半透明叠影或内容粘连；切换终态 MUST 与所点导航目标一致。
- **FR-007**: 次级页（全部目标/我的/编辑器/详情/通知等 push 顶栏）MUST 顶栏同构：返回键几何、标题字阶、栏高、左右缘四页及以上完全一致；今日/回顾 hero 头部结构维持 004 冻结稿不变。
- **FR-008**: 全部小图标按钮（铃铛/返回/日历等）MUST 具备不小于 44pt 的触达区域，视觉尺寸维持冻结稿。
- **FR-009**: 今日页头部铃铛与头像 MUST 与「今日」大标题的视觉中线共享对齐基准。
- **FR-009a**: 本轮 MUST 保持既有功能、信息结构、配色体系与文案零变化（004 冻结语言不动；「卡片零阴影」「hero 字号混用」两条经核验不属实，不修改）。
- **FR-010**: 「今日页大块空白」「切换粘连」两项 MUST 在真机/模拟器复核并留档结论：复现缺陷则修复，未复现则记录裁定依据。

### Key Entities

本轮无新增数据实体（纯界面度量/适配/动效修复；不新增持久化字段）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 同层各屏内容左右缘 x 坐标完全一致（hero 两屏同线 24、次级四页同线 16；截图叠加/自动化断言分层基准，含深浅两主题）。
- **SC-002**: 带底部安全区机型上 dock 底幕覆盖至屏幕底缘（y=0），无断层像素；无安全区机型布局与现版一致。
- **SC-003**: 今日页首卡左缘/末卡右缘与页基准偏差为 0（保留 peek 不受影响）。
- **SC-004**: dock 切页过渡时长与曲线全局单值（取自动效刻度，无逐页参数）；push 页维持平台默认转场。
- **SC-005**: 全部小图标按钮触达区 ≥44pt（逐个量取），视觉尺寸与冻结稿一致。
- **SC-006**: 既有全部功能与测试口径零回归（004 收口基线全绿），新增度量/适配用例全绿；两项待复核项结论 100% 留档。

## Assumptions

- **边距取分层基准：hero 两屏 24（003 三屏标题带基准 + 004 hero 冻结值，不动）+ 次级四页 16（列表密度档）**——2026-08-23 clarify 用户裁定（原默认案「全端单值 24」被取代）：16 为移动端行业默认基线（列表扫读密度与卡宽最优），两档差异经 push 转场自然隔离。审查文档「全端 16」单值案亦不采纳（损 hero 冻结屏气势）。次级页 20→16 偏离冻结稿原型 4pt 为有意裁定，随 D7 一并留档。
- **转场时长/曲线复用全局动效刻度既有档位**（标准减速族 ≈250ms），不新造 240ms 裸值——与审查「禁止裸数值」约束一致。
- 审查文档中 PageHeader 56dp 四页全替换、页题降 22/700、浅灰底/白卡阴影单色方案等处方与 004 冻结语言（hero 大标题两屏、双主题成对令牌、深色禁重阴影）冲突，**改造后吸收**：hero 不动、次级顶栏同构化、令牌沿用现有体系；共享顶栏/卡片/页面骨架组件属实现手段，由 plan 阶段裁定形态。
- 「卡片零阴影无层次」「今日 24/回顾 20 字号混用」两条经代码核验不属实（浅色卡均带低档阴影；两屏同为 32 字阶），本轮不修改，核验表留档。
- 「今日页大块空白」「切换粘连」两项代码层未复现，默认进真机复核（沿用既有侧载合并窗口安排），未复现则不改。
- 深色主题阴影分层口径（以亮度差表达层级）为既有契约，本轮任何改动不得引入重阴影。
