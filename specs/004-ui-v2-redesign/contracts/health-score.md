# Health Score Contract: 三大类健康度（减分制）

spec US2/FR-004 的计算与呈现契约（research D3/D4 定稿）。口径冻结，实现侧（纯函数 + provider）以此为验收基准。

## 计算口径

```text
窗口      W = [today − 6, today]                # 含今日滚动 7 天
参与集合  A = { g : g.status == active }        # 暂停/归档不参与
零记录    Z(c) = { g ∈ A(c) : ∀ r ∈ CheckIns, r.goalId ≠ g.id ∨ r.day ∉ W }
                          # 窗口内无任何记录行（打卡补签同计，一行即非零）
类分      score(c) = clamp(100 − 3 × |Z(c)|, 0, 100)
无数据    A(c) = ∅ → 该类环呈无数据态（非满分非 0）
```

- `c ∈ {健康, 习惯, 目标}`，`A(c)` 经 `iconKey → GoalIconCatalog.domain → MajorCategory` 派生（映射表见 data-model.md）
- 例：健康类 3 活跃目标、1 个近 7 天零记录 → 健康环 97

## 呈现规则（今日页三环）

| 状态 | 呈现 |
|---|---|
| 类内有活跃目标 | 该类环按 score(c) 填充，配类名（健康/习惯/目标）与分数 |
| 类内零活跃目标 | 无数据态（空置环 + 类名弱化），不显示数字 |
| 全库零活跃目标 | 环区整体隐藏，今日页空态接管 |

- 三环同心嵌套、各持一色（palette 三大类常驻色），无单一综合分数字
- 深浅主题下完成/未完成弧段均清晰可辨（FR-013）

## 复算时机（状态式，无记账）

goals 或 checkIns 任一流变化 → 健康度 provider 失效重算：打卡、补签、暂停/恢复、删除、新建均即时反映。打卡/补签一行即令该目标退出 Z(c)，类分即时回升（=「打卡即清零」语义）。

## 跨天行为

`dayTicker` 跨天 → todayProvider 变化 → 窗口整体右移：昨日的记录逐渐移出窗口，长期零记录目标保持扣分；无额外结算动作。

## 验收对账（quickstart 引用）

1. 造数：健康类 2 目标（其一 7 天前最后记录）、习惯类 1 目标（今日打卡）、目标类 1 目标（暂停）
2. 期望：健康 97 / 习惯 100 / 目标无数据（暂停不参与）
3. 操作：给健康零记录目标打卡 → 健康即时 100
4. 操作：恢复暂停目标且其 7 天零记录 → 目标环 97 出现
