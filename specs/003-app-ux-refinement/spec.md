## User Scenarios & Testing *(mandatory)*

### User Story 1 - 三 Tab 信息架构收敛与今日页头部重组 (Priority: P1)

用户在真机试用后反馈：目标页与今日页右上角的新建按钮语义重复，导航显得冗余；顶部导航条与内容像两个图层、还有分隔线；左上角问候语占着最贵的位置却没有承载账号身份。本故事把 App 收敛为**今日 / 回顾 / 我的**三个页签：目标页取消，其管理职能（浏览全部目标、编辑、暂停/恢复、删除）并入今日页的目标卡与详情动线；今日页顶部与主内容统一为同一连续图层（无分隔线、背景贯通）；左上角改为账号信息区（头像 + 昵称，点击可编辑本地资料）；右上角通知按钮从「通知设置」改为**应用内通知列表**（提醒、成就时刻、连续记录里程碑，时间倒序），通知设置迁往我的页。

**Why this priority**: 这是其余全部工作的结构地基——页签数量、目标管理入口、通知入口一旦变动，回顾页空态 CTA、我的页设置区、编辑器入口全部随之重排；先定骨架才能做表层。

**Independent Test**: 可完全通过走查验证：任意界面底部恒三页签；从今日页完成「看全部目标 → 进详情 → 编辑 → 暂停/恢复」全程不出三 Tab 结构；顶栏滚动时无分隔线无图层切换感；点头像可改昵称；点铃铛看到通知列表而非设置。

**Acceptance Scenarios**:

1. **Given** 任意页面，**When** 观察底部导航，**Then** 恰为 今日/回顾/我的 三个页签，不存在目标页签或第四入口
2. **Given** 今日页，**When** 上下滚动内容，**Then** 顶部区域与内容区背景连续、无分隔线出现，无"换了图层"的观感
3. **Given** 今日页，**When** 点击左上账号区，**Then** 进入资料编辑（头像/昵称），保存后今日页左上即时更新且重启保留
4. **Given** 今日页，**When** 点击右上铃铛，**Then** 打开通知列表（按时间倒序，含类型图标与时间），列表内没有任何设置控件
5. **Given** 今日页的目标卡，**When** 长按/进入详情，**Then** 可完成编辑、暂停、恢复、删除——原目标页全部管理职能在三 Tab 结构内可达
6. **Given** 通知列表为空，**Then** 呈现友好空态说明，而非空白

---

### User Story 2 - 新建/编辑目标页重构：分组表单 + 三类型 + 开关化提醒 + 图标库 (Priority: P1)

用户反馈新建目标页「进入后像切到另一图层（底部 Tab 消失）、表单扁平铺开无层次、设置项全是自然语言句子」；且数据模型上要求删除「多久做一次/次数/多少天」类频率问答，改为**长期 / 短期 / 习惯**三种目标类型；描述只要一句话，不问"为什么想做/怎样算做到"；提醒变成开关，开启后选频率（一天一次/三天一次/一周一次）与提醒时间；图标从一套涵盖常见目标领域的 UI 图标库中选择，颜色选择整个移除。重构后编辑器保留底部 Tab（同图层呈现），表单按「基础信息 / 类型与提醒 / 图标」分组折叠，每组用标准控件（文本框、分段选择、开关、时间选择器），不再出现自然语言句式设置项。

**Why this priority**: 创建动线是产品最高频路径，其体验与心智模型（三类型）直接决定留存；且此故事牵动数据模型与迁移，周期最长，需与 US1 并行尽早启动。

**Independent Test**: 可独立验证：在三 Tab 结构内点「新建」，底部 Tab 仍在；填一句话描述 → 选类型 →（习惯）开提醒选频率与时间 → 选图标 → 保存，全程无频率问答、无颜色选择、无"为什么/怎样算"字段；新建的目标即时出现在今日页并可打卡。

**Acceptance Scenarios**:

1. **Given** 任意页签内点新建，**When** 编辑器打开，**Then** 底部三页签保持可见可点，页面无图层切换感
2. **Given** 编辑器，**When** 浏览表单，**Then** 内容按分组折叠组织，展开后均为标准控件，无一句自然语言形式的设置项
3. **Given** 创建流程，**When** 逐步前进，**Then** 全程不出现「多久做一次/次数/多少天」类频率问题，也不出现「为什么想做」「怎样算做到」字段
4. **Given** 选择「习惯」类型并打开提醒开关，**When** 设置频率与时间，**Then** 可选 一天一次/三天一次/一周一次 与提醒时间，到点收到语气一致的提醒通知
5. **Given** 选择「短期」类型，**When** 填写截止信息，**Then** 目标呈现倒计时语义；选择「长期」则为持续型呈现，无截止概念
6. **Given** 图标选择步，**When** 打开图标库，**Then** 至少覆盖 8 类常见目标领域（如 运动/学习/健康/创作/旅行/理财/生活/冥想），无颜色选择步骤
7. **Given** 只有一句话描述，**When** 保存，**Then** 目标创建成功并出现在今日页——创建不再有必答的多段心理字段

### User Story 3 - 回顾页空状态与标题一致性 (Priority: P2)

用户反馈回顾页空状态「只有曲线框且偏上、整体不友好」，点击空状态应能直达新建目标；且回顾页左上角标题文字位置与其他页不一致。重构后：空状态竖直居中、有引导文案与「新建目标」行动按钮，情绪上是邀请而非留白；今日/回顾/我的三屏大标题的左缘与基线位置完全一致。

**Why this priority**: 空态是首次使用的第一印象、标题错位是肉眼可见的粗糙感；但两者都不动结构，排在两个 P1 之后。

**Independent Test**: 清空数据后进入回顾页：空态居中、点击 CTA 直达新建；并排截图比对三屏标题像素对齐。

**Acceptance Scenarios**:

1. **Given** 无任何目标数据，**When** 进入回顾页，**Then** 空状态竖直居中呈现，含说明文案与「新建目标」主按钮
2. **Given** 回顾页空态，**When** 点击「新建目标」，**Then** 直达新建编辑器（≤1 次交互）
3. **Given** 今日/回顾/我的 三屏，**When** 并排比对左上角标题，**Then** 文字左缘缩进与竖直位置逐屏一致

---

### User Story 4 - 我的页按主流 App 设置结构重组 (Priority: P2)

用户反馈我的页「设置区太弱，不像主流 App」。参考头部 iOS 应用的设置页结构重组：顶部账号卡（头像/昵称/编辑入口），下方为分组列表（每组若干行：行首图标 + 标题 + 行尾值/开关/箭头），典型分组为 通知（提醒设置，自今日页迁入）、目标偏好、数据（备份与导出/导入）、外观、关于（版本号）。行控件可即时生效（开关类）或进二级页（chevron 类）。

**Why this priority**: 承接自今日页迁出的通知设置与本特性新增的账号资料，是三 Tab 收敛后的配套收纳层；结构性强但不阻塞其他故事。

**Independent Test**: 走查我的页：账号卡可编辑资料；通知设置在我的页内可达且功能等价（开/关提醒、按目标调整）；备份导出/导入回归通过；每行为标准设置行样式。

**Acceptance Scenarios**:

1. **Given** 我的页，**When** 查看，**Then** 呈现「账号卡 + 分组设置列表」结构，行内为 图标+标题+（值|开关|箭头）标准形态
2. **Given** 我的页通知分组，**When** 调整提醒设置，**Then** 效果与原今日页通知设置完全等价（含按目标的提醒时机）
3. **Given** 我的页，**When** 使用备份导出后导入覆盖，**Then** 数据一致（V7 备份回归在新结构下仍通过）
4. **Given** 深色模式，**When** 查看我的页，**Then** 全部分组与行在深浅两态下可读、对比达标

---

### User Story 5 - 既有数据零丢失迁移 (Priority: P2)

本特性删除频率问答（多久做一次/次数/多少天）、移除颜色选择、并让「为什么想做/怎样算做到」退出创建动线——老版本创建的目标带有这些字段与既有打卡/记录。迁移必须做到：全部目标、打卡、记录、补签数据 100% 保留；旧频率语义映射到新类型（高频节律 → 习惯，有截止 → 短期，其余 → 长期）；旧颜色仅从界面退场不参与迁移计算；退役字段在库中保全不删（为未来留余地），只是不再出现在任何界面与表单。

**Why this priority**: 用户已在真机长期使用、存量数据真实存在；任何丢失都不可接受。排在 P2 是因为其形态是伴随实现与收尾的回归保障，而非独立交付面。

**Independent Test**: 用带旧字段的存量库启动新版本：目标数量、打卡次数、最近记录逐项对账；被映射为习惯的目标按原节奏继续提醒。

**Acceptance Scenarios**:

1. **Given** 旧版本数据（含频率/颜色/为什么/怎样算 字段），**When** 升级启动新版本，**Then** 目标、打卡、记录、补签全部完整保留，计数逐项一致
2. **Given** 旧目标原为每日 3 次频率，**When** 迁移后查看，**Then** 该目标呈现为「习惯」类型且打卡计数连续不中断
3. **Given** 旧目标带截止日，**When** 迁移后查看，**Then** 呈现为「短期」类型，倒计时正确
4. **Given** 迁移后的任意界面，**When** 走查，**Then** 不出现颜色选择、频率问答、"为什么/怎样算"字段的任何残留

### Edge Cases

- 账号资料未填写时今日页左上显示什么？（默认头像 + 默认昵称「我」，不强迫填写）
- 通知列表很长时的呈现？（按天分组、可滚动，超过保留上限的旧条目自动清理）
- 只有一句话描述的极简目标，详情页如何呈现不空？（图标 + 描述 + 类型徽章 + 打卡节奏，占位由系统补足）
- 习惯目标关闭提醒开关后已有排程怎么办？（即时取消未触发的排程，历史不受影响）
- 旧数据中频率无法清晰映射（如每周 2 次非整节律）时归入哪类？（默认「习惯」，提醒按最接近档位 一周一次）
- 三 Tab 收敛后深链/快捷入口（如通知点击落地页）是否仍可达？（路由重排后全部入口回归验证）
- 备份文件跨版本互导（新导出 → 旧版本导入）？（新文件含类型字段但保持向后兼容的结构，旧版本可读基础字段）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: App 底部导航 MUST 恒为三个页签（今日/回顾/我的），任何界面与流程中不存在第四入口；目标页整体移除
- **FR-002**: 原目标页的管理职能（浏览全部目标、编辑、暂停/恢复、删除）MUST 全部在三 Tab 结构内可达（今日页目标卡 → 详情/编辑动线），迁移前后能力对等
- **FR-003**: 今日页顶部区域与主内容区 MUST 呈现为同一连续图层：背景贯通、无分隔线，滚动过程中不得出现异色横条或图层切换观感
- **FR-004**: 今日页左上角 MUST 为账号信息区（头像 + 昵称），点击进入资料编辑（头像、昵称），资料本地存储、即时生效、重启保留；未填写时显示默认头像与默认昵称
- **FR-005**: 今日页右上角通知按钮 MUST 打开应用内通知列表：按时间倒序、含类型图标与时间、支持按天分组滚动；列表内不含任何设置控件；空态有友好说明
- **FR-006**: 通知（提醒）设置 MUST 从今日页迁至我的页设置区，能力等价（总开关、按目标的提醒调整），今日页不再承载设置职能
- **FR-007**: 回顾页空状态 MUST 竖直居中、含引导文案与「新建目标」主按钮，点击直达新建编辑器（≤1 次交互）
- **FR-008**: 今日/回顾/我的 三屏左上角大标题 MUST 位置一致（左缘缩进与竖直基线逐屏相同）
- **FR-009**: 我的页 MUST 按主流设置页结构重组：账号卡置顶 + 分组列表（行 = 图标 + 标题 + 行尾值/开关/箭头），分组至少覆盖 通知 / 数据（备份导出导入）/ 关于（版本）
- **FR-010**: 新建/编辑目标页 MUST 在三 Tab 容器内呈现（底部页签保持可见可点），不得有"切换图层"的全屏跳转感
- **FR-011**: 编辑器表单 MUST 分组折叠组织（基础信息 / 类型与提醒 / 图标），组内一律标准控件（文本框、分段选择、开关、时间选择器）；不得出现自然语言句式设置项
- **FR-012**: 目标类型 MUST 为 长期 / 短期 / 习惯 三选一；创建与编辑流程不得出现「多久做一次 / 次数 / 多少天」频率问答
- **FR-013**: 习惯型目标的提醒 MUST 为开关形态：开启后可选频率（一天一次 / 三天一次 / 一周一次）与提醒时间；关闭即时取消未触发排程
- **FR-014**: 目标描述 MUST 仅为一句话（单字段短文本）；「为什么想做」「怎样算做到」不得出现在创建/编辑流程与任何界面
- **FR-015**: 图标 MUST 从内置图标库选择，覆盖 ≥8 类常见目标领域（运动/学习/健康/创作/旅行/理财/生活/冥想 等量级）；颜色选择从产品界面整体移除
- **FR-016**: 升级迁移 MUST 零丢失：既有目标/打卡/记录/补签 100% 保留；旧频率映射到三类型（高频节律→习惯、有截止→短期、其余→长期；无法清晰映射默认习惯 + 一周一次）；退役字段（频率明细/颜色/为什么/怎样算）在存量数据中保全但不再上屏
- **FR-017**: 既有验证场景（001 的 V1–V8 回归口径）MUST 在新信息架构下全部通过（允许入口位置等价调整，不允许能力回退）

### Key Entities

- **目标 Goal**: 属性演进为——一句话描述；类型（长期/短期/习惯）；图标（图标库引用）；提醒（开关 + 频率档 + 时间，习惯型有效）；短期型的截止信息；既有打卡/记录关系不变；退役属性（频率明细、颜色、为什么、怎样算）保留于数据层但退出所有界面
- **通知条目 NotificationItem**: 应用内通知列表的一行——类型（提醒/成就/里程碑）、标题、时间；由本地数据推导，有过期清理策略
- **账号资料 Profile**: 头像 + 昵称，本地存储；为将来账号系统预留结构（本特性不含后端账号）
- **设置项 SettingsEntry**: 我的页分组列表的一行——图标、标题、行尾控件（值/开关/箭头）与目标页（二级页或即时开关）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 全 App 页签恰为 3 个（走查 + 界面结构核对），原目标页职能在三 Tab 内 100% 可达
- **SC-002**: 新建一个习惯目标（描述 + 类型 + 提醒 + 图标）≤ 8 次交互、≤ 60 秒完成，且全程底部页签可见
- **SC-003**: 旧版本升级后 目标/打卡/记录/补签 计数逐项 100% 一致（迁移对账测试）
- **SC-004**: 回顾页空态 ≤1 次交互直达新建；三屏标题并排比对左缘与竖直位置一致
- **SC-005**: 编辑器与我页设置区 0 个自然语言句式设置项（全部为标准控件形态——走查断言）
- **SC-006**: 新旧结构并存屏数 = 0（三 Tab 新骨架全覆盖；既有界面走查无旧导航/旧表单残留）
- **SC-007**: V1–V8 功能回归在新信息架构下全部通过（打卡主路径仍 ≤2 次交互）

## Assumptions

- **账号系统本特性不含后端**：今日页账号区 + 我的页账号卡为本地资料（头像/昵称），结构与视觉为将来接真账号预留；用户"感觉要接账号系统了"按预留位理解，不在本特性引入登录/云端
- **图标库采用"开源授权图标集策展 + 统一包装"路线**（用户明示"或者你在网上搜一下"）：优先选用许可宽松的成熟图标集按目标领域策展分类，必要时少量自绘补充；具体选型在计划阶段定，规避版权风险
