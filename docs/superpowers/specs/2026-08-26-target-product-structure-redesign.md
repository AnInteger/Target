# Target 产品结构与目标管理重构设计

日期：2026-08-26  
状态：产品方向已确认，待页面级设计与实施计划

## 1. 背景

当前版本已经具备目标创建、进展记录、里程碑、提醒、历史记录、目标状态管理和跨目标趋势等能力，但这些能力没有建立在统一的产品概念上，导致以下问题：

- “长期目标 / 短期目标 / 习惯”被设计成互斥且不可修改的类型，但长期、短期描述时间范围，习惯描述执行方式，三者不属于同一维度。
- “下一步计划”与“未完成里程碑”实际表达相近，却在首页卡片、目标详情和记录面板中以不同名称重复出现。
- 进展记录、里程碑完成和创建下一里程碑被放进同一个保存动作，事实记录与规划编辑混在一起。
- 今日页以当日记录和综合评分描述所有目标，不适合不需要每天推进的长期目标。
- 今日卡片、全部目标卡片和需要关注卡片重复展示类似内容，但没有针对行动、管理和回顾场景形成不同信息密度。
- 目标详情承担了新增、删除和排序里程碑等结构编辑职责，与目标编辑页重复。
- “我的”重复提供目标统计、目标管理和新建目标入口。
- 现有“进展”页主要展示七天评分趋势和建议，缺少用户真正做过什么、完成了什么的跨目标历史与成果。

本设计以“记录并管理个人目标”为产品核心，建立从规划、推进到回顾的完整闭环。

## 2. 产品定位

Target 是一个个人目标管理与记录 App，帮助用户：

1. 看见自己正在管理哪些目标。
2. 理解每个目标当前推进到哪个阶段。
3. 记录为目标实际做过的事情。
4. 查看已完成的里程碑与已达成的目标。
5. 按时间回顾近期进展和累计成果。

产品同时支持长期目标、阶段性目标和习惯培养，但不要求用户每天为每个目标产生记录。

## 3. 核心概念

### 3.1 目标

目标是用户想实现或持续培养的结果。目标可以有日期、执行节奏、里程碑和提醒，也可以只包含名称。

### 3.2 里程碑

里程碑是用户预先规划的阶段成果。所有目标都可以拥有里程碑，包括持续培养类目标。

- 目标编辑页负责新增、删除、改名和排序。
- 目标详情负责查看、标记完成和撤销完成。
- 第一条未完成里程碑作为当前里程碑。

### 3.3 进展记录

进展记录描述用户某次实际做了什么，是事实，不承担计划编辑职责。

记录包含目标、日期、创建时间、内容和保存时的当前里程碑上下文。记录面板不创建下一步、不新增里程碑，也不修改目标设置。

### 3.4 执行节奏

执行节奏描述用户希望多久推进一次，与目标日期和里程碑彼此独立。用户可以不设置固定节奏，也可以选择每天、每周若干次或指定星期。

### 3.5 成果

成果是已经发生的结果，包括完成里程碑、达成目标，以及依据真实记录汇总出的持续推进表现。成果展示在回顾中，不与通知或规划混为一谈。

### 3.6 目标状态

目标状态包括：

- 进行中：当前正在推进。
- 已暂停：暂时不参与日常关注，但历史保留。
- 已达成：用户确认目标已经完成。
- 已归档：从日常管理中隐藏，可取消归档。

删除不属于状态。删除会清除目标及其记录，是单独的危险操作。

## 4. 取消互斥目标类型

“长期 / 短期 / 习惯”不再作为互斥且不可修改的领域类型。目标能力由彼此独立的设置组合而成：

- 是否设置目标日期。
- 是否设置执行节奏。
- 是否设置里程碑。
- 是否设置提醒。

例如：

- “养成跑步习惯”可以长期持续、每周三次，并设置“坚持 21 天”和“完成 5 公里”里程碑。
- “拿到潜水证”可以设置截止日期和多个里程碑，但不设置固定执行频率。
- “学习摄影”可以没有截止日期和固定频率，只通过里程碑与进展记录推进。

现有目标类型仅用于旧数据迁移时推导初始设置，不继续作为新目标的必填选择。

## 5. 信息架构

主导航调整为三个职责明确的页面：

```text
今日：当前关注与快速记录
目标：全部目标与生命周期管理
回顾：跨目标历史、近期进展与成果
```

辅助页面包括：

- 目标详情。
- 新建/编辑目标。
- 我的。
- 设置。
- 通知。

“我的”通过今日页头像进入，不占据主导航。

## 6. 今日页

今日页回答“我现在关注哪些目标”和“如何快速留下进展”。它不要求所有目标每天产生记录。

### 6.1 目标概览

原当日型概览改为跨时间尺度的目标概览：

- 进行中：当前进行中目标数。
- 已达成：累计已达成目标数。
- 近 7 天进展：最近七天进展记录数，并可补充“推进了 N 个目标”。

概览不展示当日全目标完成率，也不展示“健康 / 习惯 / 目标”百分制状态环。

### 6.2 今日目标卡

今日使用行动型卡片，每张卡片展示：

- 目标名称。
- 当前里程碑。
- 已完成里程碑数与总数。
- 最近一次真实进展及日期。
- 目标日期或当前执行节奏。
- 记录进展主操作。

卡片不提供编辑、暂停、归档或删除等管理动作。

### 6.3 今日关注范围

进行中目标与今日展示容量不得继续混为同一概念。现有“最多五个活跃目标”的硬限制退役。进行中目标可以超过五个；今日页展示的关注目标可以由独立关注标记或清晰、可解释的优先规则选出。

具体采用手动关注还是系统排序，在今日页实施设计时确定，但不得重新限制用户只能拥有五个进行中目标。

## 7. 目标页

目标页是全部目标与目标管理的唯一主入口，使用高密度列表，不复制今日行动卡。

### 7.1 列表行

每一行显示：

- 图标。
- 目标名称。
- 当前状态。
- 一条关键摘要，例如当前里程碑、最近进展或里程碑完成比例。
- 始终可见的更多操作按钮。

点击整行进入目标详情；点击更多按钮打开管理菜单。长按可以保留为辅助快捷方式，但不能成为发现菜单的唯一方式。

### 7.2 筛选与排序

第一级按状态筛选：全部、进行中、已暂停、已达成、已归档。

分类作为第二级筛选，不优先于目标状态。默认按状态分组，同组内按最近更新排序。

### 7.3 操作菜单

菜单根据目标状态显示合法操作：

- 进行中：记录进展、编辑、暂停、标记达成、归档、删除。
- 已暂停：恢复、编辑、标记达成、归档、删除。
- 已达成：查看成果、重新开启、归档、删除。
- 已归档：取消归档、删除。

菜单分为推进、管理和危险操作三组。删除始终单独显示并二次确认；归档不得代替达成，也不得与删除使用相同危险等级。

## 8. 目标详情

目标详情是单个目标的完整档案，页面顺序为：

1. 目标概览。
2. 当前里程碑。
3. 记录进展主操作。
4. 里程碑列表。
5. 历史时间线。
6. 编辑与生命周期管理入口。

详情页允许标记或撤销里程碑完成，不允许新增、删除、改名和排序里程碑。

历史默认使用时间线，展示进展记录、里程碑完成和目标达成等事件。日历作为历史的辅助查看方式；通用目标不再被固定限制为最近七天打卡视图。设置执行节奏的目标可以额外显示本周执行情况。

## 9. 记录进展

今日页和目标详情共用同一个记录面板。重复入口属于不同上下文下的同一核心动作，不视为功能冗余。

记录面板包含：

- 目标名称。
- 当前里程碑提示。
- 记录日期，可选择过去日期。
- 本次进展内容。
- 保存操作。

面板删除以下能力：

- 下一步计划。
- 新建下一里程碑。
- 编辑、删除或排序里程碑。
- 目标设置。

里程碑完成通过详情页独立操作产生明确成果事件，不与一次普通进展记录强制绑定。

## 10. 新建与编辑目标

新建目标不使用模板，也不要求用户先选择目标类型。新建和编辑使用同一套字段结构。

### 10.1 表单结构

1. 基本信息：目标名称必填；图标与分类可调整。
2. 时间设置：不设日期或指定目标日期。
3. 执行节奏：不设固定节奏、每天、每周若干次或指定星期。
4. 里程碑：可选列表，支持新增、删除、改名和排序。
5. 提醒：可选开关、时间和提醒规则。

只填写目标名称即可创建。日期、执行节奏、里程碑和提醒均为可选设置，不强迫用户在创建时完成全部规划。

新建成功后进入目标详情，使用户能够确认目标状态；编辑成功后返回原目标详情。

图标与分类解耦。图标可以提供分类建议，但分类不能继续由图标静默决定，也不能作为生成抽象目标评分的依据。

## 11. 回顾页

现有“进展”页重构为真正的回顾页，承担跨目标历史和成果展示。

### 11.1 时间范围

提供本周、本月和全部范围，并允许按目标或分类筛选。

### 11.2 事实概览

展示所选范围内：

- 进展记录数。
- 产生进展的目标数。
- 完成里程碑数。
- 达成目标数。

进行中和已归档数量属于目标库存状态，放在目标页筛选中；它们不作为回顾成果指标。

### 11.3 成果与时间线

回顾展示：

- 已完成里程碑。
- 已达成目标。
- 依据记录汇总出的连续推进成果。
- 跨目标活动时间线。

现有七天百分制趋势和依赖“下一步清晰度”的专业建议退役。需要关注的信息使用可验证事实表达，例如临近截止、长期无进展或计划频率未达到，不再使用无法直接验证的综合分数。

## 12. 我的、设置与通知

### 12.1 我的

保留头像、昵称、设置、数据备份与关于入口。删除进行中、本月完成、已归档三个统计，以及目标管理和新建目标入口。

### 12.2 设置

只承担全局偏好：外观、通知总开关与权限、每日概要、数据备份和关于。删除进行中目标数与补记说明。逐目标提醒由目标编辑页设置，设置页只提供全局控制或提醒总览。

### 12.3 通知

通知只保留需要用户处理的内容，例如计划提醒、临近截止、长期未推进和权限异常。里程碑完成、连续记录和目标达成属于回顾成果，不作为长期通知历史重复展示。

## 13. 重复与复用原则

- 今日和详情都可以进入记录进展，因为它们服务快速操作和单目标上下文。
- 详情和回顾都可以展示历史，因为它们分别是单目标历史和跨目标历史。
- 今日和目标页都展示目标，但必须使用行动卡与管理列表两种不同形态。
- 新建目标的常规入口只在目标页；首次空状态可以提供上下文入口。
- 目标结构只在编辑器维护；详情只负责推进和查看。
- 成果只在回顾集中展示，通知不承担成果档案职责。

## 14. 数据与迁移原则

- 旧目标类型迁移为日期、执行节奏和提醒等独立设置。
- 旧下一步计划如果已经保存为未完成里程碑，则保留为普通里程碑；不再保留独立下一步字段。
- 现有有效 CheckIn 迁移或解释为进展记录，保留日期、内容和补记信息。
- 现有里程碑完成时间、目标达成时间和历史记录必须完整保留。
- 已归档目标迁移后允许取消归档。
- 旧百分制趋势可以停止新增，不将不同规则的数据继续连接为同一趋势。

## 15. 实施边界

本规格确认产品模型、页面职责和关键流程，不冻结最终视觉稿、精确文案、今日关注的选择方式或列表像素尺寸。页面级设计可以继续讨论这些细节，但不得违反以下边界：

- 不恢复互斥目标类型。
- 不恢复独立下一步计划。
- 不在记录面板编辑规划结构。
- 不让目标详情再次承担里程碑结构编辑。
- 不复制今日行动卡作为目标管理列表。
- 不以每日记录作为所有目标的统一成功标准。
- 不以隐藏的长按手势作为目标管理菜单的唯一入口。

## 16. 建议实施顺序

1. 重构目标领域模型、状态机和数据迁移。
2. 重构新建/编辑目标与里程碑维护。
3. 新增目标主页面和完整管理菜单。
4. 精简今日页并替换目标概览与行动卡。
5. 重构目标详情、记录面板和历史时间线。
6. 将进展页重构为回顾页。
7. 精简我的、设置和通知，移除旧评分运行链。

每一步均应保留旧数据可读，并通过真实数据库迁移和核心用户旅程验证。
