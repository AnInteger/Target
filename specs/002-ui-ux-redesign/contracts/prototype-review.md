# Contract: 原型交付与评审门禁（流程契约）

本契约约束 FR-001（原型先行）的执行细节：原型怎么交付、怎么算"通过"、通过前禁止什么。

## 1. 交付物形态（MUST）

- 自包含 HTML：单文件、零外部请求（字体走系统栈、图标内联 SVG）、`file://` 直接可开
- 手机逻辑视口 393×852（iPhone 基准），页面内自带手机外框或按视口居中呈现
- 动效以 CSS 动画示意并可在页面内触发演示（如点击打卡出反馈）
- 状态覆盖：每屏至少呈现"典型态 + 1 个边界态"（空态/深色之一）；深色以页面内切换或并列画板表达
- 存放与命名：`design/prototypes/direction-{a|b|c}.html`（方向对比）、`screen-{name}.html`（核心屏）；`index.html` 为评审入口（方向对比入口 + 屏索引 + 各屏通过状态 + 指向 reviews.md）

## 2. 评审流程（MUST）

```
产出原型 → 用户在浏览器查看 → design/reviews.md 记录意见（原话）→
  ├─ 修改后再审：修订原型，轮次 +1，再次送审
  └─ 通过：reviews.md 记录"通过"+日期 → 解锁该屏的 Flutter 实现任务
```

- 每屏默认预期 1 轮、至多 2 轮（spec 假设）；第 2 轮仍不通过 → 升级讨论（口头对齐方向，不无限迭代）
- 评审记录字段：`屏/方向标识 · 轮次 · 日期 · 用户意见原话 · 结论 · 修订说明`

## 3. 门禁（MUST / 禁止事项）

1. 任一屏的最新结论非"通过"时，**禁止**对该屏做 Flutter 实现（tasks 层面表现为实现任务被原型任务阻塞）
2. 风格方向未定（FR-009 记录缺失）时，**禁止**产出具名 `screen-*.html` 与任何令牌翻译
3. 目标定义模型的字段集未通过 `screen-editor.html` 评审时，**禁止**写数据库迁移（R5 envelope 除外——只许设计文档推进，不许动 schema）
4. 实现完成后的屏以"原型 ↔ 实现"并排核对（Web release 面截图对照）作为该屏收尾动作

## 4. 通过标准（验收口径）

"通过"= 用户明确表示认可（如回复"通过/可以/就这个"或选定方案），且浅/深两态、边界态均在原型中可见。仅"还行/先这样吧"等含糊表述按"修改后再审"处理并追问具体意见。
