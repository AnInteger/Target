**与 003 裁决的关系**：003 的交互与结构裁决（整卡可点、最新记录行、编辑器平铺分组等）**不再约束实现**——本 feature 推翻呈现层与交互结构，仅保功能能力（清单见上）与文案语域；今日页结构随之重定义（头部 + 健康度环 + 关注卡轮播 + 查看全部入口）；003 预留的「当日聚合待设计」由「三大类健康度环」接续作答

## Clarifications

### Session 2026-08-22 · 三项裁决（spec 澄清问答）

- Q1（底部导航与「我的」去向）→ A：照图收敛为**今日/回顾两页签 + 中央凸起圆形新建按钮**；「我的」整页收进今日页头像二级入口（头像点击从「资料编辑」变为「我的页入口」），其全部职能（主题切换、通知设置、备份等）≤2 次点击可达
- Q2（Focus 主推卡机制）→ 用户自定义方案：**关注卡为可左右滑动的卡片轮播**（每个活跃目标一张主色关注卡），提供「查看全部」入口打开全部卡片列表；不引入排他「置顶」概念、无新增数据属性，轮播顺序按最近互动优先（派生排序）
- Q3（页面大标题语言）→ A：**保持中文**（「今日」「回顾」+ 中文日期行），不引入装饰性英文大标题

### Session 2026-08-23 · 三大类健康度体系（US2 进度环升级）

- Q: 今日页进度环用什么形态呈现三大类健康度？ → A（用户自定义）：**三环嵌套**——三个同心环，每个大类（健康/习惯/目标）一个环，各环独立显示该类健康度分数，无单一综合分数字
- Q: 三大类健康度的评分算法采用哪种机制？ → A（用户选定）：**阶梯减分制**——每类满分 100 起，类内目标长时间未更新按档扣分，分数随荒废时间走低
- Q: 减分制的扣分速率怎么定？ → A（用户自定义）：**按类内未完成目标数扣**——每类分 = 100 − 3 ×（该类近一周零记录的活跃目标数）；一个目标一周没更新即扣 3 分，N 个未完成扣 N×3
- Q: 打卡之后分数怎么恢复？ → A：**打卡即清零**——打卡/补签后该目标即时退出「未完成集合」，其大类环分即时回升（状态式口径，天然达成清零语义，无需落库记账）
- Q: 八个领域小类各自归属到哪个大类？ → A：**健康**=运动、健康、冥想；**习惯**=生活；**目标**=学习、创作、旅行、理财（静态映射，新建目标经小类自动归属，无需手选）
- Q: 本次推翻的范围边界放在哪一层？ → A（用户选定）：**连交互结构也可重排**——只保留功能能力（创建三类型目标/打卡/补签/编辑/暂停恢复/删除/提醒/通知/备份/资料/统计），003 的交互与结构裁决不再约束实现，唯文案语域规则保留；图中未覆盖的按钮、文案、组件按基准图风格自行补充或修改（推翻「仅换装」旧表述）
- Q: 图中未覆盖界面的自行设计稿要不要先经评审再实现？ → A：**全部原型评审门禁**——延展界面先出可走查原型稿，用户逐屏裁决冻结后才进入实现（003 T007 模式，FR-015）
- Q: 社交/宠物两个后增小类归属哪个大类？ → A（用户选 B）：**归「健康」**——健康=运动/健康/冥想/社交/宠物；习惯=生活；目标=学习/创作/旅行/理财（推翻 plan 阶段按「习惯」补全的代定方案，FR-014 据此改写为十领域口径）

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 全局设计语言 v2：双主题基准与全部界面重做 (Priority: P1)

用户提供了同一套设计的深色版（图 01/04）与浅色版（图 02）基准图，要求**推翻原有风格设计、按基准图实施**：App 拥有成体系的视觉语言（深浅两套完整主题、大圆角卡片、克制留白、统一的按钮/标签/进度组件形态），且推翻范围**含交互结构**——全部现有页面（今日、回顾、我的、目标编辑器、目标详情、通知列表、资料编辑、调试时钟等）的布局、控件形态、按钮、文案、交互方式均按基准图风格重做，旧风格零保留；基准图未覆盖的界面按图风格延展设计，**先出原型稿经用户评审冻结后实现**。全部既有功能能力（创建三类型目标/打卡/补签/编辑/暂停恢复/删除/提醒/通知/备份/资料/统计）在新 UI 中保持可达。主题默认跟随系统深浅色，并在「我的」页提供 跟随系统 / 浅色 / 深色 三档手动切换，切换即时生效并持久保留。

**Why this priority**: 双主题设计基准是其余全部故事的地基——今日页骨架、回顾页图表、关注卡轮播、底部导航的视觉实现都消费这套基准；先立 tokens 再翻页面，避免各屏各自为政。

**Independent Test**: 在系统深色与浅色两种模式下分别走查全部页面：无一处文字不可读、无一处残留旧风格组件；既有功能动线全部走通；在「我的」页切换三档主题即时生效，重启后保留。

**Acceptance Scenarios**:

1. **Given** 系统处于深色模式，**When** 逐页走查（今日/回顾/我的/编辑器/详情/通知列表），**Then** 全部页面呈现基准图 01/04 所示深色视觉语言（深底、深灰卡片、主色/强调色体系），无残留旧风格组件
2. **Given** 系统处于浅色模式，**When** 逐页走查，**Then** 全部页面呈现基准图 02 所示浅色视觉语言（浅灰底、白色卡片），与深色版同构
3. **Given** 「我的」页的主题设置，**When** 在 跟随系统/浅色/深色 三档间切换，**Then** 全 App 即时切换且无需重启；重启后选择保留
4. **Given** 按新风格重做后的目标编辑器与目标详情页，**When** 走查功能动线，**Then** 创建三类型目标、选分类图标、设提醒、打卡与选填描述、补签、编辑、暂停/恢复、删除全部可达——功能能力零丢失，呈现与交互形态为基准图风格
5. **Given** 基准图未覆盖的界面（编辑器/详情/我的/通知/全部列表等），**When** 进入实现前，**Then** 已有经用户评审冻结的原型稿作为实现基准（FR-015）
6. **Given** 任意页面，**When** 检查文案，**Then** 无口语化解释句、无本地存储位置说明（文案语域为保留的产品规则）

### User Story 2 - 今日页骨架 v2：新头部 + 三大类健康度环 (Priority: P1)

今日页按基准图 01/02 的骨架重组：**头部**为「星期与日期行 + 页面大标题（中文，Q3 裁决）+ 右上账号头像入口（Q1 裁决：进入「我的」页）」，替代现有左上账号区横排布局；头部下方是**三大类健康度环**（003 预留「当日聚合待设计」形态的最终答案，2026-08-23 澄清升级）：三个同心嵌套环，**健康 / 习惯 / 目标**三大类各一环、各环独立显示该类健康度分数（0–100，无单一综合分）——目标的领域小类静态归属到三大类（映射见 FR-014），健康度按阶梯减分制计算（口径见 FR-004）：每类满分 100，近一周零记录的活跃目标每个扣 3 分，打卡/补签即时回升。今日页主体为关注卡轮播（US3），纵向目标列表与分类筛选迁往「全部目标列表」（US3 场景 4）。无活跃目标时环区与轮播让位于新建引导空态。

**Why this priority**: 今日页是最高频首页；健康度环把「人整体状态好不好」放上首页并随坚持/荒废实时涨落，头部确立页面骨架，是关注卡轮播（US3）与导航改版（US4）的容器。

**Independent Test**: 造 3 个不同小类目标（跨两大类，其一近 7 天未打卡）：三环嵌套各自分数与手工核算一致；对未打卡目标打卡后其大类环分即时回升；点头像进入「我的」页。

**Acceptance Scenarios**:

1. **Given** 今日页，**When** 查看头部，**Then** 呈现中文「星期, 日期」行 + 大标题「今日」+ 右上头像（点击进入「我的」页）；头部与内容区同一连续图层、无分隔线
2. **Given** 健康类 3 个活跃目标中 1 个近 7 天零记录，**When** 查看健康度环，**Then** 健康环显示 97 分；三环分别对应 健康/习惯/目标 三大类、各环独立计分，不出现单一综合分数字
3. **Given** 某大类下近 7 天零记录的活跃目标有 N 个，**When** 计算该类健康度，**Then** 分数 = 100 − N×3，下限 0
4. **Given** 某目标处于未完成集合（近 7 天零记录），**When** 对其打卡或补签，**Then** 该目标即时退出未完成集合，其大类环分即时回升（恢复语义 = 打卡即清零）
5. **Given** 今日存在暂停目标，**When** 计算健康度，**Then** 暂停目标既不计入未完成集合、也不参与扣分
6. **Given** 某大类下无任何活跃目标，**When** 查看三环，**Then** 该环呈无数据态（非满分、非 0 分的空置呈现）
7. **Given** 今日无任何活跃目标，**When** 进入今日页，**Then** 环区与轮播让位于新建引导空态（不留空转的环）

### User Story 3 - 关注卡轮播：横向滑动浏览 + 查看全部 (Priority: P1)

按基准图 02（借鉴意图即「关注卡片」）与 Q2 裁决，今日页健康度环下方为**关注卡轮播**：每个活跃目标一张主色填充的醒目大卡（状态标签 + 目标名 + 一句话描述 + 主行动按钮进入该目标记录动线 + 辅助信息行），可**左右滑动**切换，卡序按最近互动优先（最近有记录或创建的在前，派生排序、不落库）；轮播区提供**「查看全部」入口**，打开**全部目标列表**——承载目标浏览与管理职能（进详情、编辑、暂停/恢复、删除均可达），列表与卡片的具体形态按基准图风格延展设计、经原型评审定稿（FR-015）。暂停/删除的目标实时移出轮播。

**Why this priority**: 关注卡轮播是基准图今日页的视觉焦点与核心浏览方式（Q2 用户裁决），牵动今日页纵向结构与「全部目标列表」的新建，须与 US2 骨架同批定型。

**Independent Test**: 造 3 个目标并给其中 1 个打卡：今日页轮播呈现 3 张关注卡、最近打卡的居首；左滑可切换；点主行动按钮直达对应详情；「查看全部」打开列表页，筛选与 003 管理动线可用。

**Acceptance Scenarios**:

1. **Given** 3 个活跃目标，**When** 进入今日页，**Then** 轮播呈现 3 张主色关注卡（状态标签+目标名+一句话描述+主行动按钮），最近互动的目标排在首位，左右滑动可逐张浏览
2. **Given** 关注卡，**When** 点击主行动按钮，**Then** 进入该目标的记录/详情动线（打卡、补签、历史记录可达；具体形态按新风格设计、原型评审定稿）
3. **Given** 轮播区「查看全部」入口，**When** 点击，**Then** 打开全部目标列表：目标浏览与分类筛选可达，进详情/编辑/暂停/恢复/删除全动线可达（形态经原型评审定稿）
4. **Given** 全部目标列表的分类筛选，**When** 点选某分类，**Then** 列表仅显示该分类目标；筛选为空时呈现空态说明而非空白
5. **Given** 轮播中某目标被暂停或删除，**When** 回到今日页，**Then** 该目标实时移出轮播，无悬空卡片；仅剩 1 个目标时轮播退化为单卡（可滑动的分页指示随卡片数隐藏）
6. **Given** 无任何活跃目标，**When** 进入今日页，**Then** 无轮播（由 US2 空态接管）
7. **Given** 轮播卡与列表中同一目标，**When** 对比，**Then** 数据一致（最新记录、状态语义同源），轮播仅为呈现层级而非数据副本

### User Story 4 - 底部导航改版与「我的」页去向 (Priority: P2)

按 Q1 裁决照图收敛：底部导航改为**今日 / 回顾两页签 + 中央凸起圆形新建按钮**；「我的」整页收进今日页头像二级入口（头部头像点击进入），其全部职能（本地资料、主题切换、通知设置、备份导出/恢复等）保持完整、≤2 次点击可达。原第三页签移除后，任意页面导航结构恒定；中央按钮点击直达目标编辑器。

**Why this priority**: 导航是全局结构决策且决定今日页头部的最终交互（头像语义变化），但改动本身集中、可在视觉基准定型后快速落地。

**Independent Test**: 任意页面底部恒为「今日/中央按钮/回顾」；点中央按钮直达新建编辑器；点头像进「我的」页，主题/通知/备份职能逐项可用。

**Acceptance Scenarios**:

1. **Given** 任意页面，**When** 查看底部导航，**Then** 恰为 今日 / 中央凸起新建按钮 / 回顾，不存在第三页签或第四入口，视觉为新基准语言，全程恒定
2. **Given** 中央新建按钮，**When** 点击，**Then** 直达目标编辑器（≤1 次交互），创建三类型目标的动线功能完整
3. **Given** 今日页头像，**When** 点击，**Then** 进入「我的」页；主题切换（US1）、通知设置、备份导出/恢复、资料编辑逐项可达（≤2 次点击），无职能丢失
4. **Given** 回顾页签，**When** 在回顾页操作，**Then** 底部导航结构不变（回顾页无头部头像时，「我的」入口仍可从今日页到达，导航不因页面而异）

### User Story 5 - 回顾页 v2：周平均 + 每日活动 + 本周目标三区块 (Priority: P2)

回顾页按基准图 04 重构为三区块：**周平均区块**——本周完成率环形进度 + 与上周的环比增减；**每日活动区块**——本周七天（周一至周日）的逐日完成度圆点行，按完成情况着色；**本周目标区块**——本周活跃目标卡列表（目标名 + 线性进度条 + 进度百分比），右上「查看全部」入口。顶部提供周切换（查看往周）。空态含引导文案与「新建目标」CTA 直达编辑器（形态按新风格设计）。

**Why this priority**: 回顾页是留存的引擎，但依赖视觉基准与统计口径（US1/US2 先行定型进度语义），故列 P2。

**Independent Test**: 造 2 个目标并跨 3 天打卡：周平均值与手工计算一致；七天圆点中打卡日着色；本周目标卡进度与目标详情页数据同源；切换到上一周数据正确。

**Acceptance Scenarios**:

1. **Given** 本周有打卡数据，**When** 进入回顾页，**Then** 依序呈现 周平均（环+环比）/ 每日活动（七天圆点）/ 本周目标（列表）三区块，数据与底层记录一致
2. **Given** 本周与上周完成率分别为 X 与 Y，**When** 查看周平均区块，**Then** 环比增减方向与大小正确（上周无数据时呈现「无可比较」类语义，不显示错误的增减）
3. **Given** 本周某日无任何记录，**When** 查看每日活动区块，**Then** 该日圆点呈未完成态；未来日期不呈已完成态
4. **Given** 「查看全部」入口，**When** 点击，**Then** 可浏览全部目标的进度（不限于本周有记录者）
5. **Given** 周切换控件，**When** 切换到往周，**Then** 三区块数据切换为该周口径；无数据周呈现对应空态
6. **Given** 无任何目标数据，**When** 进入回顾页，**Then** 空态含引导文案与「新建目标」CTA，点击直达新建编辑器

### User Story 6 - 初始屏 v2：黑底极简品牌屏 (Priority: P2)

按基准图 03 重做首次启动的初始屏：纯深色底、品牌图形居上、一句产品主张（中文、正式语域）、单一主行动按钮（「开始使用」类文案）进入主界面。图中英文文案、服务条款、社交证明数字均为模板残留，MUST NOT 引入；本地无账号体系，初始屏不出现任何注册/登录环节。

**Why this priority**: 初始屏是第一印象但独立于主流程，可最后落地；依赖 US1 视觉基准定稿。

**Independent Test**: 清除应用数据后冷启动：初始屏呈现品牌图形+主张+主按钮；点击主按钮进入今日页；再次启动不再出现。

**Acceptance Scenarios**:

1. **Given** 首次启动，**When** 打开 App，**Then** 呈现深色极简初始屏：品牌图形 + 一句中文主张 + 主行动按钮，无其他干扰元素
2. **Given** 初始屏，**When** 点击主行动按钮，**Then** 进入今日页（或既有引导动线），全程无注册/登录/条款环节
3. **Given** 已完成首次启动，**When** 再次启动，**Then** 不再出现初始屏，直达今日页

### Edge Cases

- 系统深浅色在 App 运行中切换时，全屏即时跟随（含已打开的对话框/通知列表浮层），无半旧半新混排
- 今日活跃目标数为 0：三环区与轮播隐藏（不留空转的环），空态接管
- 某大类下无活跃目标：该环呈无数据态（空置呈现，非满分非 0 分）
- 类内全部目标荒废：扣分穿底夹 0，环不低于 0 分
- 轮播仅 1 个目标：退化为单卡、无滑动指示；轮播目标全部暂停/删除：实时清空并转入空态，无悬空卡
- 目标当日刚好完成最后打卡：其关注卡状态标签反映完成态，行动语义不悬空
- 深色模式下进度环/线性进度/圆点等图表元素的完成与未完成态对比度足够，色弱可辨（不单靠红绿）
- 回顾页查看往周时目标已删除：该周统计按历史记录口径呈现，不因目标删除而崩坏
- 极长目标名（一句话描述换行 3 行以上）在关注卡、列表卡、回顾卡三种容器内不破坏布局
- 「查看全部」列表为空（全部目标被暂停/删除）：呈现列表空态而非空白页
- 系统字体放大（无障碍最大字号）：头部、关注卡、导航文字不溢出裁切

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供深色与浅色两套完整主题，视觉语言以基准图 01/02/04 为准（色彩体系、字体层级、圆角、留白、组件形态），全部页面统一消费同一套设计基准
- **FR-002**: 主题 MUST 默认跟随系统深浅色，「我的」页 MUST 提供 跟随系统/浅色/深色 三档选择，切换即时生效并持久保留
- **FR-003**: 今日页头部 MUST 呈现中文「星期, 日期」行 + 大标题「今日」+ 右上头像入口（进入「我的」页），头部与内容区同一连续图层、无分隔线
- **FR-004**: 今日页 MUST 呈现三大类健康度环：三个同心嵌套环，健康/习惯/目标各一环、独立计分（0–100，无综合分）；口径 = 100 − 3 ×（该大类下近 7 天零记录的活跃目标数），下限 0，纯派生不落库；打卡/补签 MUST 即时退出未完成集合并回升该类分数；暂停目标 MUST NOT 参与扣分；无活跃目标的大类环 MUST 呈无数据态；无任何活跃目标时环区让位于空态
- **FR-005**: 今日页 MUST 呈现关注卡轮播：每个活跃目标一张主色大卡（状态标签+目标名+一句话描述+主行动按钮直达详情），可左右滑动，卡序按最近互动优先（派生排序）；提供「查看全部」入口打开全部目标列表（纵向卡片 + 分类筛选行 + 003 全部管理职能）；暂停/删除的目标 MUST 实时移出轮播
- **FR-006**: 全部目标列表 MUST 承载目标浏览与全部管理职能（进详情、编辑、暂停/恢复、删除）及分类筛选（全部 + 各分类，单选，筛选为空呈现空态说明）；卡片与列表的具体形态按基准图风格延展设计、经原型评审定稿，不受旧版交互裁决约束
- **FR-007**: 底部导航 MUST 改为 今日 / 中央凸起圆形新建按钮 / 回顾 两页签结构，任意页面恒定；中央按钮直达目标编辑器（≤1 次交互）；「我的」页 MUST 收进今日页头像二级入口且全部职能 ≤2 次点击可达
- **FR-008**: 回顾页 MUST 呈现三区块：周平均完成率（环+与上周环比）、每日活动（本周七天逐日完成度）、本周目标列表（目标名+线性进度+百分比）+「查看全部」入口
- **FR-009**: 回顾页 MUST 支持周切换查看往周；上周无数据时环比呈现「无可比较」语义；未来日期不呈已完成态
- **FR-010**: 回顾页空态 MUST 含引导文案与「新建目标」CTA 直达编辑器
- **FR-011**: 首次启动 MUST 呈现深色极简初始屏（品牌图形 + 一句中文主张 + 主行动按钮），点击进入主界面；后续启动不再出现；MUST NOT 出现注册/登录/服务条款/社交证明内容
- **FR-012**: 全部界面文案 MUST 遵循 003 文案语域裁决：正式 App 文案、无口语化解释句、无本地存储位置说明
- **FR-013**: 图表类元素（健康度环/圆点行/线性进度/环比）MUST 在深浅两主题下完成态与未完成态均清晰可辨，不单靠色相区分
- **FR-014**: 十个领域小类 MUST 静态归属三大类：健康=运动/健康/冥想/社交/宠物，习惯=生活，目标=学习/创作/旅行/理财；新建目标经所选小类自动归属大类（用户无需手选）；大类在界面以中文呈现（健康/习惯/目标），三大类在健康度环与关注卡视觉上各持一色
- **FR-015**: 基准图未覆盖的界面（目标编辑器/目标详情/我的页/通知列表/全部目标列表等）MUST 先产出可走查的原型稿，经用户逐屏评审冻结后方可进入实现（延展设计门禁）
- **FR-016**: 既有功能能力 MUST 在新 UI 中全部可达：创建三类型目标（长期/短期/习惯）、分类图标选择、提醒开关（频率+时间）、打卡与选填描述、补签、编辑、暂停/恢复、删除、应用内通知列表与设置、备份导出/恢复、本地资料、统计回顾；呈现与交互形态不受旧版裁决约束

### Key Entities *(include if feature involves data)*

- **主题偏好（Theme Preference）**: 新增用户设置项，取值 跟随系统/浅色/深色，持久保留
- **大类-小类映射（静态配置）**: 健康=运动/健康/冥想/社交/宠物，习惯=生活，目标=学习/创作/旅行/理财——内置映射，不落库
- **三大类健康度（派生统计）**: 每大类 100 − 3 ×（近 7 天零记录活跃目标数），下限 0——纯派生，不落库
- **周统计（派生统计）**: 周完成率、逐日完成度、环比——纯派生口径，不落库
- **关注卡序（派生排序）**: 活跃目标按最近互动（最近记录/创建）优先——纯派生，不落库，无新增目标属性

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 深浅两种主题下走查全部页面，任意页面无可读性失败项（文字对比度、组件态辨识）——0 处混排旧风格
- **SC-002**: 今日页骨架与基准图 01/02 逐区块对应（头部/进度环/关注卡轮播/查看全部/导航），走查确认率为 100%
- **SC-003**: 主题三档切换即时生效率 100%（无重启、无残留），重启保留 100%
- **SC-004**: 三大类健康度、周平均、逐日完成度三项统计与手工核算一致（构造数据全量对账，含打卡/补签后的分数回升路径）
- **SC-005**: 首次启动初始屏出现且仅出现一次，主行动按钮进入主界面 ≤1 次点击
- **SC-006**: 全部既有功能能力在新 UI 中回归零丢失（创建/打卡/补签/编辑/暂停/恢复/删除/提醒/通知/备份/资料/统计全动线走查通过）

## Assumptions

- 本 feature 基于 003 完成态代码库（003 仅余真机侧载验证，不阻塞本 spec）
- 界面语言保持中文（Q3 裁决）：基准图中的英文示例文案（目标名、按钮、条款、英文日期格式）均为模板残留，不逐字引入
- 「查看全部」落为全部目标列表（载体形态以独立页为默认，经原型评审定稿）
- 基准图中不借鉴的内容：示例目标名、头像缩写、服务条款、社交证明数字、注册登录环节（本地无账号体系）
- 分类具备色彩语义（图 02 进度环按分类分色的模式）可纳入设计基准，具体映射在 plan 阶段定稿
- 旧版（003）的交互与结构裁决不再约束实现——推翻范围含交互结构，仅保功能能力（FR-016 清单）与文案语域；延展设计一律经原型评审门禁（FR-015）后实现
- 健康度「近一周」= 含今日的滚动 7 天窗口；「零记录」以该窗口内有无任何打卡/补签记录判定（补签计入）；大类界面名用中文 健康/习惯/目标（「目标」大类与实体「目标」同名属语境可区分的接受项，如后续造成理解负担可在 plan 阶段更名）
- 轮播首卡的初始位置为最近互动目标（与卡序一致），不记忆上次滑动位置
