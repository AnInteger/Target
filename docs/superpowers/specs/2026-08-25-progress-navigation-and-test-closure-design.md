# Target 进展页、导航与核心闭环设计规格

日期：2026-08-25  
状态：已实现并验证

## 1. 背景与目标

首页新设计已经得到真机认可，但仍有四类问题需要收口：

- 底部导航在图标和文字下方保留过多视觉空白。
- “查看全部”与“我的”使用不同的路由层级和页面转场。
- “回顾”不保存反思或决策，与首页“进展”和“需要关注”重复。
- 目标详情的最近七天记录缺少日历语义，难以辨认星期、日期、状态和补记入口。

本阶段将首页与进展页重新分工，补齐目标记录、分数刷新、进展解释、日期补记和目标管理的可验证闭环，并统一导航与品牌图标。

## 2. 已确认的产品决策

1. “回顾”退役，第二页签改为“进展”。
2. 首页只保留目标状态卡和关注目标轮播。
3. 首页现有趋势图、专业建议和“需要关注”完整迁移到进展页，不在两页重复。
4. 不保存“回顾结果”，也不创建反思、确认或决策记录。
5. 删除 `/review` 与 `target://review`，新增 `/progress` 与 `target://progress`，不保留重定向。
6. 目标详情的“今日记录”保留单卡结构，分为“今日进展”和“最近 7 天”两个明确区块。
7. 底部导航采用“目标环 + 趋势线”图标。
8. App 图标采用白底“目标轨迹”：蓝色路径、墨色起点、绿色目标点。
9. “查看全部”和“我的”使用同一个根级全屏 push/pop 转场。

## 3. 信息架构

### 3.1 今日 `/today`

自上而下：

1. 日期、标题、通知与个人入口。
2. 目标状态卡。
3. 关注目标轮播。
4. 页面自然结束。

首页只回答“当前状态如何”和“现在推进什么”，不再承载趋势解释和关注清单。

### 3.2 进展 `/progress`

自上而下：

1. 标题“进展”和范围“近 7 天”。
2. 健康、习惯、目标三条真实日期趋势。
3. 各维度当前值与可访问的感叹号入口。
4. 展开的三段式建议：指标原理、当前解读、行动建议。
5. “需要关注”目标列表。
6. 无趋势、无建议和无关注项的真实空状态。

进展页直接消费当前 `goalProgressProvider`，不增加持久化实体。关注项进入对应目标详情。

### 3.3 目标详情 `/goal/:id`

“今日记录”单卡重构为：

- 标题“今日进展”。
- 当前里程碑或待规划提示。
- 主操作“记录进展”。
- 分区标题“最近 7 天”和明确日期范围。
- 星期、日期、今日态、已记录态和可补记态。
- “已记录 / 可补记”图例。
- “查看日历”入口。

过去且无记录的日期可直接打开补记面板；已有记录的日期进入当天记录；今日通过主按钮记录。完整日历支持查看和补记更早日期。所有记录继续复用现有原子事务：新增 CheckIn、可选完成当前里程碑、可选创建下一里程碑。

## 4. 路由、动画与导航

### 4.1 路由结构

```text
Root navigator
├── /onboarding
├── /profile                 全屏 push，隐藏 dock
├── /goals-all               全屏 push，隐藏 dock
├── /settings                全屏 push，隐藏 dock
└── StatefulShellRoute
    ├── /today
    │   ├── /goal-editor
    │   └── /goal/:id
    └── /progress
```

- 删除 `/review` 路由和 `ReviewView`。
- `target://progress` 映射到 `/progress`。
- `target://review` 不再识别。
- 全部目标与我的使用同一个 `CustomTransitionPage`：轻微淡入并从右侧进入，反向退出；持续时间、曲线和根 navigator 完全一致。

### 4.2 底部导航

- 视觉内容高度从 84dp 压缩至约 68dp。
- iPhone 底部安全区保留为系统空间，不参与图标列布局。
- 图标、标签和选中短线集中在 68dp 内容区上半部。
- 今日图标为定制目标环，进展图标为定制趋势线，均由 Flutter `CustomPainter` 绘制。
- 中央新增按钮维持凸起圆形和至少 44×44dp 命中区。

## 5. 组件边界与数据流

### 5.1 新建组件

- `features/progress/progress_view.dart`：页面组合和空状态。
- `features/progress/progress_trend_card.dart`：七日趋势、当前值和建议展开。
- `features/progress/attention_goal_list.dart`：需要关注列表和目标跳转。
- `app/dock_glyphs.dart`：目标环与趋势线绘制。

### 5.2 修改组件

- `TodayView` 删除趋势和关注清单，只组合状态卡与轮播。
- `GoalDetailPage` 重构今日记录卡和日期点击语义，不复制仓库逻辑。
- `router.dart` 新增 progress 分支、统一全屏转场并压缩 dock。
- `copy.dart` 删除回顾文案，新增进展、日期图例和空状态文案。

### 5.3 数据流

```text
Goal / CheckIn / Milestone Drift streams
                 ↓
        goalProgressProvider
          ↙             ↘
 Today 状态卡       Progress 趋势/建议/关注

记录进展面板 → ProgressRepository transaction
              → Drift streams 自动刷新
              → 首页状态、进展趋势、关注列表同步更新
```

页面不得手动复制评分公式，也不通过手工 invalidate 模拟刷新。

## 6. 旧回顾运行链清理

删除运行时消费链：

- `ReviewView`、回顾路由和导航文案。
- `reviewsProvider`、`settlementServiceProvider`。
- App 启动时自动创建周回顾快照的调用。
- 周一通知中的“上周回顾已生成”提示。
- 只服务旧回顾 UI 的 `weekOverview`、`dayActivities`、`weekRateOf` 及相关展示类型。
- 无 UI 消费方的 Busy Mode 启动恢复与 Provider；其存量数据不再影响当前状态。

暂不执行删表迁移。`WeeklyReviews`、旧 Frequency/Busy 数据表及备份键保持可读写，避免破坏旧数据库和旧备份；它们不再有运行时业务消费方。后续若正式决定停止读取旧备份，再单独进行版本化数据移除。

## 7. 品牌与应用图标

新增白底目标轨迹 SVG 母版：

- 背景：不透明 `#FFFFFF`，全出血，不烘焙圆角。
- 路径：进展蓝。
- 起点：近墨色。
- 终点：完成绿。
- 内边缘允许极浅灰描边，避免浅色壁纸上边界消失。

由母版生成：

- iOS AppIcon 全尺寸和 1024px Marketing 图标。
- Android launcher 与 adaptive icon 前景/背景。
- 不提供另一套深色 App 图标，深色主屏仍使用白底版本。

## 8. 错误、空状态与可访问性

- 记录保存失败：面板保持打开并保留输入，显示可重试错误。
- 目标 ID 无效或目标已删除：返回今日并显示提示，不保留空白详情页。
- 无进展数据：趋势卡显示说明，不绘制虚假水平线。
- 无需要关注项：显示“当前没有需要优先处理的计划”。
- 日历状态同时使用文字、图标、边框和颜色，不只依赖色相。
- 所有日期、感叹号、导航图标和卡片入口具备语义标签及至少 44×44dp 命中区。
- 浅色、深色和跟随系统主题均使用语义颜色令牌。

## 9. 当前测试资产审计

当前测试套件共 162 项：136 个 unit test，26 个 widget test。最近一次完整运行全部通过。

### 9.1 已有优势

- 数据库迁移、备份新旧格式、损坏文件和字段往返覆盖充分。
- 新评分权重、阈值、无数据语义、分类覆盖和建议选择有纯函数测试。
- 记录进展事务覆盖成功、空下一步、失败回滚和里程碑位置。
- 新建目标覆盖主要字段、类型切换草稿、图标分类和短期目标保存。
- 通知计划、提醒权限、目标图标目录、资料和主题设置覆盖较细。
- 已有应用级 widget 流程覆盖首次启动、从首页创建目标、从关注卡记录进展及打开目标详情。

### 9.2 冗余与遗留

- `health_score_test.dart` 的 12 项验证已退役的 `100 - 3N` 算法，与新 `goal_progress_test.dart` 重复且结论冲突，应随旧模型删除。
- `settlement_test.dart` 的 8 项验证不再存在的周回顾结算与 Busy Mode 决策，应随运行链删除。
- `stats_engine_test.dart` 中仅服务旧回顾页面的周概览、每日活动和单目标周卡测试应删除；自然日、补记、撤销、周留痕和小组件仍使用的统计测试保留。
- `widget_test.dart` 中“回顾仍是独立分支”必须替换为进展页主流程。
- `reminder_service_test.dart` 中周一附加回顾提示的测试应删除或改为普通每日概要。
- Frequency/Busy/WeeklyReview 的存量表测试缩减为“旧数据仍可读取和备份”，不继续测试无 UI 的业务行为。

### 9.3 当前核心缺口

1. 没有一条应用级用例验证“记录进展后评分、趋势和关注列表同步刷新”。
2. 新建只完整保存了短期目标；长期和习惯缺少 UI 到数据库的保存闭环。
3. 没有验证详情日历补记后历史、分数和日期状态同步更新。
4. 没有覆盖全部目标页面的编辑、暂停、恢复、标记达成和删除。
5. 没有验证“查看全部”和“我的”使用同一转场并隐藏 dock。
6. 首页与进展页在 320/375/430dp、浅色/深色下缺少统一回归矩阵。

## 10. 目标测试结构

### 10.1 领域与仓库测试

保留并补齐：

- 三种目标创建与字段不变量。
- 原子记录、补记、撤销和事务回滚。
- 评分阈值、七日趋势、关注原因排序和建议内容。
- 暂停、恢复、达成、编辑和删除的状态转换。
- 备份、迁移、提醒和主题持久化。

### 10.2 组件测试

- 进展页区块顺序、建议展开、真实目标图标和空状态。
- 详情记录卡的星期、日期范围、今日、已记录和可补记状态。
- dock 68dp 内容高度、安全区和两枚新图标。
- 全屏转场持续时间、曲线、进入/返回方向和 dock 隐藏。
- 白底 App 图标资产存在、无透明通道且尺寸完整。

### 10.3 四条应用级用户旅程

1. **创建旅程**：通过 UI 分别创建长期、短期和习惯目标，验证数据库字段、首页出现和全部目标可管理。
2. **推进旅程**：创建带里程碑目标 → 记录进展 → 完成里程碑 → 新建下一步 → 验证 CheckIn、里程碑、分数、趋势和关注项自动更新。
3. **日期旅程**：进入详情 → 选择过去空日期补记 → 验证日历状态、历史记录、统计和分数更新。
4. **管理旅程**：全部目标 → 编辑 → 暂停 → 恢复 → 标记达成或删除 → 验证首页、进展和列表同步变化。

这些旅程使用真实 Router、Riverpod 与 Drift 内存数据库，不 mock 核心仓库；平台通知、分享和文件选择仍使用网关替身。

## 11. 验收标准

1. 首页不再出现进展趋势和需要关注列表。
2. 第二页签为“进展”，且不存在 `/review` 运行路由。
3. 记录一次进展后，首页状态与进展页数据无需重启即同步刷新。
4. 详情卡能一眼识别星期、日期、今日、已记录和可补记状态。
5. “查看全部”和“我的”的进入/返回动画一致，页面内不显示 dock。
6. 底部导航无多余视觉空白，并正确避让系统安全区。
7. iOS/Android 使用新的白底目标轨迹图标。
8. 遗留测试删除后，核心测试数量可以下降，但四条应用旅程全部通过。
9. `flutter analyze`、完整 `flutter test` 和 `flutter build web --release` 通过。
